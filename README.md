# ПОС - Преподавательская Оценка Студентов

Консольное приложение на C#. Можно завести студентов и критерии, выставить и отменить оценки, посчитать итог и выгрузить его в CSV.
## Запуск

```
dotnet run
```

Пункт меню `11` прогоняет сквозной сценарий: студенты и критерии → оценки → итог → экспорт в `demo_results.csv`.
## Логика решений

- Студент, критерий и оценка - сущности, у каждой есть `Id`, и они существуют независимо.
- Рубрикатор - это все критерии в `ICriterionRepository`.
- Итог нигде не хранится, а каждый раз считается из текущих оценок и рубрикатора в `FinalGradeService`. Поэтому он всегда согласован с оценками.
- Итог считается по 10-балльной шкале. Если по критерию нет оценки, за него ставится 0.
- У одного студента по одному критерию может быть только одна оценка.
## Карта DDD
| Понятие             | Где в коде                                                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ubiquitous Language | `Student` (студент), `Criterion` (критерий), `Evaluation` (оценка), `FinalGradeService` (итог)                                                                                                    |
| Entity              | `Student`, `Criterion`, `Evaluation` - у них есть `Id`, их сравнивают по идентичности                                                                                                             |
| Value Object        | `Score` (балл) - неизменяемый `record`, сравнивается по значению и проверяет себя в конструкторе                                                                                                  |
| Инварианты          | `Score` ≥ 0; вес > 0; `max_score` > 0; балл ≤ максимума критерия (`Criterion.CheckScore`); оценка только по критерию из рубрикатора (`EvaluationFactory`); одна оценка на пару студент + критерий |
| Repository (порты)  | `IStudentRepository`, `ICriterionRepository`, `IEvaluationRepository` лежат в Domain, реализации - в Infrastructure                                                                               |
| Domain Service      | `FinalGradeService` - итог зависит сразу от студента, всех критериев и всех оценок, поэтому он не принадлежит ни одной сущности                                                                   |
## Архитектура

Выбрана **Ports and Adapters (Hexagonal)**.

| Папка            | Что внутри                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| `Domain`         | сущности, VO, фабрика, стратегии, domain service, интерфейсы репозиториев. Ни от чего не зависит |
| `Application`    | `PosFacade` (сценарии), порт `IReportExporter`, DTO для вывода `StudentResult`, `EvaluationView` |
| `Infrastructure` | адаптеры: хранилища в памяти, `CsvReportExporter`                                                |
| `Presentation`   | `ConsoleUi` - консольное меню                                                                    |
| `Program.cs`     | composition root: регистрация всего в DI-контейнере                                              |

Домен не знает ни про консоль, ни про CSV. Инфраструктура реализует интерфейсы из Domain и Application, т.е. зависимости направлены внутрь.
## Паттерны GoF

| Группа        | Паттерн  | Где                                                                                                   | Какую боль закрывает                                                                                                                                                                                        |
| ------------- | -------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Порождающий   | Фабрика  | `Domain/EvaluationFactory`                                                                            | Оценка создаётся только в одном месте, и там же проверяется, что студент и критерий существуют, балл в пределах критерия и оценки по этой паре ещё нет. Нельзя случайно создать «12 из 10» в обход проверок |
| Структурный   | Facade   | `Application/PosFacade`                                                                               | Все сценарии собраны в одном классе, а UI только читает ввод и печатает результат                                                                                                                           |
| Поведенческий | Strategy | `IGradeStrategy`, `WeightedGradeStrategy`, `AverageGradeStrategy`, используются в `FinalGradeService` | Правило итога можно поменять (пункт меню 9), не меняя сервис. Новое правило - это новый класс                                                                                                               |
## DI

Используется `Microsoft.Extensions.DependencyInjection`. Все зависимости регистрируются в `Program.cs`, а классы получают их через конструктор.
